# How The Web Works

## DNS
DNS is basically the phonebook of the internet.
When I type google.com my browser does not know where to go.
It asks DNS — DNS looks it up and returns the IP address.
Then my browser knows where to send the request.

Record types I learned:
A record — gives you the IPv4 address for a domain
AAAA record — same but for IPv6
CNAME — points one domain to another domain
MX — tells you where to send emails for that domain
TXT — just text, used for verification stuff

## HTTP
HTTP is how browsers and servers talk to each other.
Every time I open a website I am sending an HTTP request
and getting an HTTP response back.

GET — I am asking for something, parameters show in the URL
POST — I am sending something, parameters hidden in the body

Status codes I need to remember:
200 — worked fine
301 — moved permanently
401 — not logged in
403 — logged in but not allowed
404 — does not exist
500 — server broke

## How a Website Actually Works
Frontend is what I see — HTML structure, CSS styling, JavaScript behaviour.
Backend is what I do not see — the server processing my requests.
Database is where everything is stored — users, posts, passwords.

## What Actually Happens When I Open a Website
1. I type a URL
2. Browser asks DNS for the IP
3. DNS returns the IP
4. Browser sends HTTP GET request
5. Server processes it and sends back HTML
6. Browser renders it into what I see

## Other Components

Load Balancer
Sits in front of multiple servers and distributes traffic between them.
If one server goes down the load balancer stops sending traffic to it.
Uses round robin or weighted algorithms to pick which server gets the request.
Does health checks to make sure all servers are running properly.

CDN
Content Delivery Network.
Hosts static files like images, CSS, JavaScript across servers worldwide.
Sends the file from the nearest server to me — makes websites faster.

Database
Where websites store everything — users, passwords, posts, settings.
Common ones: MySQL, MongoDB, PostgreSQL, MSSQL.
Web server talks to the database to fetch or store data.

WAF
Web Application Firewall.
Sits between my request and the web server.
Checks requests for attack patterns, blocks bots, rate limits traffic.
If it flags my request as an attack it drops it — never reaches the server.

Web Server
Software that listens for HTTP requests and serves content back.
Common ones: Apache, Nginx, IIS, NodeJS.
Serves files from a root directory — /var/www/html on Linux.

Virtual Hosts
One web server can host multiple websites using virtual hosts.
Checks the hostname in my HTTP request and serves the correct website.
Each website mapped to its own folder on the server.

Static vs Dynamic Content
Static — never changes. Images, CSS, JavaScript files served as they are.
Dynamic — changes based on the request. Generated by backend languages.
Backend languages: PHP, Python, Ruby, NodeJS.
Frontend is what I see. Backend processes everything behind the scenes.
